# План миграции hd-models на Nuxt

Статус: в работе. Составлен по итогам разбора текущего проекта и согласованных решений.

## Контекст

`hd-models` — каталог коллекции масштабных моделей мотоциклов Harley-Davidson (производство
Maisto, масштаб 1:18). Сейчас состоит из двух частей:

- `client/` — Vue 3 SPA на Vite: вся реальная функциональность (47 коллекций, ~279 позиций,
  542 изображения, поиск и отметки статусов);
- `server/` — заготовка на Express 5, в которой реализован только `GET /`; `mysql2`,
  `sequelize`, `bcryptjs`, `jsonwebtoken` объявлены, но не используются.

Цель миграции: одно full-stack приложение на Nuxt вместо пары client + server.

### Уточнения после проверки фактами

Первичный разбор делался только файловыми инструментами и дал три неверных вывода. Ниже —
фактическое состояние, проверенное в оболочке:

- **Git-репозиторий существует**: ветка `main`, remote `origin` →
  `https://github.com/u1tima/hd-models.git`, в истории 630 файлов, 540 из них — изображения.
  `git init` не требуется.
- **Корневой `package.json` существует** (`moto-models`, MIT, автор Vitali) и содержит только
  два скрипта-обёртки: `client` и `server`. Это не yarn workspaces, а просто точка входа.
- **Изображения уже в истории git** — 542 файла, 62,8 МБ. LFS не нужен, вопрос снят.
- **Есть незакоммиченная работа**: 12 изменённых файлов и новые `client/src/pages/`,
  `client/public/hd-1-18/series-45/`, `S-36-05-Photoroom-new.jpg`. Это чужой труд в процессе,
  его нельзя терять при in-place перезаписи.
- **`server/config.env` отслеживается git и уже в удалённом репозитории**, хотя содержит
  параметры подключения к MySQL. Отдельная задача безопасности, вне миграции.
- **Коллекция Series 45 недоделана**: данные ссылаются на шесть изображений
  `S-45-01-Photoroom.jpg` … `S-45-06-Photoroom.jpg`, а на диске лежит только `S-45-01.jpg`.
  Первый подтверждённый случай битых ссылок — на шаге 6 ожидается больше.

## Зафиксированные решения

| Вопрос | Решение |
|---|---|
| `server/` (Express) | Влить в Nitro, Express удалить |
| Рендеринг | Сначала SPA (`ssr: false`), SSR — отдельным шагом после |
| UI-библиотека | Ant Design Vue 4 остаётся |
| Где размещать | Корень репозитория `D:\web\hd-models` |
| Деплой | Не выбираем, локальная разработка |
| Страховка | Коммит текущего состояния (репозиторий уже существует) |
| Логика поиска | Починить (переписать на `computed`) в рамках миграции |
| Версия Nuxt | Nuxt 4 (актуальная стабильная) |

Структурное следствие: у Nitro каталог API — это `<корень проекта>/server/`, то есть ровно та
папка, куда переезжает Express. Поэтому Nuxt-проект разворачивается в корне репозитория, а не
внутри `client/`.

## Целевая структура

```
hd-models/
├─ app/
│  ├─ app.vue                  ← бывший App.vue (ConfigProvider/StyleProvider)
│  ├─ assets/scss/             ← colors.scss + main.scss
│  ├─ components/              ← 6 компонентов, перенос 1:1
│  ├─ pages/                   ← series / models / news / index
│  ├─ stores/useModelStore.ts  ← @pinia/nuxt
│  ├─ types/                   ← IMotorcycle, ISeriesMotorcycle
│  └─ data/                    ← 48 файлов, импорты не трогаем
├─ public/hd-1-18/             ← 542 jpg, пути один-в-один
├─ server/                     ← Nitro: api/, utils/db.ts
├─ nuxt.config.ts
├─ eslint.config.ts            ← адаптация текущего flat-config
└─ package.json                ← yarn
```

Ключевой приём против лишней работы: алиас `@` → `app/` в `nuxt.config.ts`, тогда ~50 импортов
вида `@/interfaces/...` и `@/data/...` в файлах данных остаются нетронутыми.

## Шаг 0 — предпосылки

Все три пункта обязательны до первой строки Nuxt-кода.

1. **Починить ACL рабочей папки — ВЫПОЛНЕНО.** `pwsh` падал на `grantWrite(D:\web\hd-models)`,
   из-за чего в рабочей папке не выполнялась ни одна команда. Скриптом добавлен полный доступ
   текущего пользователя и право смены владельца на `D:\web\hd-models`; изменение проверено
   повторным чтением прав. Прежние права сохранены, команда отката и отчёт лежат в
   `D:\web\hd-models-acl-recovery\`. Проверка: команды в рабочей папке выполняются.
2. **Страховка.** `git init` не нужен — репозиторий уже есть. Вместо инициализации: коммит
   текущего состояния (включая незакоммиченную работу) как точка отката. LFS не нужен,
   изображения уже в истории.
3. **Baseline.** Запустить текущий `client` и снять скриншот `/series` — единственный объективный
   критерий, что перенос ничего не сломал.

Отдельная задача, вне рамок миграции: `server/config.env` отслеживается git и уже отправлен в
удалённый репозиторий, хотя содержит параметры подключения к MySQL. Убирать из индекса и из
истории — по отдельному решению.

## Шаг 1 — каркас Nuxt 4

- Инициализация в корне, yarn как менеджер пакетов.
- Зависимости: `nuxt`, `@pinia/nuxt` + `pinia`, `ant-design-vue@4` + `@ant-design/icons-vue` +
  `@ant-design-vue/nuxt`, `sass-embedded`, `@nuxt/eslint` + перенос текущих eslint/oxlint пакетов,
  `vue-tsc`.
- `nuxt.config.ts`: `ssr: false` на первую итерацию, alias `@` → `app/`, `additionalData` со
  `colors.scss` (перенос из `client/vite.config.ts`), `css: ['~/assets/scss/main.scss']`
  (там reset AntDV из `client/src/scss/main.scss`).
- `eslint.config.ts` — адаптация текущего flat-config: добавить ignore-паттерны Nuxt-артефактов,
  сохранить `vue/script-indent: tab`.
- Точка проверки: пустой Nuxt стартует, `nuxt typecheck` и eslint проходят.

## Шаг 2 — статика

## Шаг 5 — снос старого

Удаляются `vite.config.ts`, `index.html`, `env.d.ts`, `tsconfig.app.json`, `tsconfig.node.json`,
`client/src/`, старый `eslint.config.ts`, `client/package.json`, `client/yarn.lock`,

- Скрипт-сверка: 279 записей в данных vs существующие файлы в `public/` (попутно соберётся список
  пустых `catalogImage` — их в данных много, например вся коллекция Sons of Anarchy: 6 из 6

- Скриншот `/series` против baseline.

## Шаг 7 — SSR (отдельная итерация)

Только после того, как SPA стабильно работает: `ssr: true`, проверка гидрации AntDV (cssinjs —
главный источник FOUC), `nitro.prerender` для статики, `useSeoMeta` по сериям и моделям,
`@nuxt/image` вместо голого `<img>` в `ModelCard.vue`.

## Отложено сознательно

MySQL-API поверх 279 записей, логин/настройки/каталоги из меню, перенос отметок
`isEnabled`/`isOrdered` в БД, деплой-preset. Отметки на этой итерации остаются в TS-файлах.

## Главные риски

1. **Ant Design Vue + SSR** — cssinjs-библиотека капризна к SSR, поэтому SSR вынесен в самый
   конец, а не делается «заодно».
2. **Пути картинок** — 279 абсолютных путей, привязанных к корню `public/`; перенос статики
   строго 1:1, любой сдвиг = битые изображения.
3. **In-place перезапись** — mitigated только git-коммитом из шага 0; без него откат невозможен.
4. **Права доступа Windows** — блокировка снята на шаге 0; полный доступ выдан только на
   `D:\web\hd-models`, за его пределами ограничения сохраняются.

## Порядок работы

Шаг 0 → 1 → 2 → 3 → 4 → 5 → 6, с точками проверки после каждого. Шаг 7 — по отдельному запросу.

### Шаги 3 и 4 — выполнены

- Перенесены через `git mv`: `data` (48 файлов), `interfaces`, `components` (6), `stores`,
  `pages` (3). Всего 63 переименования.
- Отступление от плана: папка `interfaces` **не переименована** в `types`. Переименование
  потребовало бы правки импортов в ~20 файлах данных, содержащих русские комментарии в UTF-8;

  поэтому компонент фильтров не менялся.
- `Series.vue` переведён на `storeToRefs` — это обязательное следствие перехода на `computed`:
  при деструктуризации обычного реактивного объекта теряется реактивность, а прежний код
  неявно опирался на мутацию массива по ссылке.
- Добавлен `app/pages/index.vue` с редиректом на `/series`: раньше корневой маршрут не
  обрабатывался вообще.
- В `.vue`-файлах отключено правило `no-undef`: ESLint не видит авто-импорты Nuxt
  (`definePageMeta`), а TypeScript их знает через `.nuxt/imports.d.ts`.
- Удалены 6 неработающих заглушек `defineComponent({ name })` — внутри `<script setup>` они
  ничего не делают.
- Проверки после переноса: `nuxt typecheck` exit 0, `eslint` exit 0, `nuxt build` exit 0,
  маршруты `/`, `/series`, `/news`, `/models` отвечают 200, данные каталога присутствуют

### Исправление прежнего разбора

Утверждение из первичного анализа о том, что сброс фильтра не восстанавливает список, **неверно**:
пустая строка содержится в любой строке, поэтому поиск с пустым запросом возвращает все позиции.
Реальная причина переписать стор — мутация общего реактивного массива на месте и неявная
зависимость реактивности компонента от этой мутации, а не потеря данных.
